Bookatlas: what works, what is simulated, and what publishing needs

This is an audit of the current development app and its implementation, not a certification that every interactive flow has passed an end-to-end test. No real reader campaign was sent and no test book was published.

Main finding: the original Multimodal Ingest Studio reported a published eBook, studio audiobook, and delivered campaigns without creating those deliverables. The legacy publishing and campaign-send paths are now blocked. The real publishing pipeline is not yet implemented.

What was actually checked

  • Live HTTP checks: public health, catalog, and category endpoints returned HTTP 200. Anonymous requests to manager statistics and email-dispatch logs returned HTTP 401.
  • Public desktop screenshot: the catalog renders without requiring sign-in. Internal-tool links remain visible in the public navigation. One resource returned HTTP 404; its cause has not yet been isolated.
  • Implementation review: publishing, campaign processing, reading/audio controls, checkout, account access policy, catalog persistence, and the principal frontend API calls were inspected.
  • Configuration check: Gemini and Supabase credentials are now configured. Both model-metadata checks passed. Supabase accepted the connection, but explicit GET queries confirmed that the app tables are absent. Resend's sending domain is verified and a sender mailbox has been configured. No email has been sent.
  • Safety changes verified: five focused unit tests passed for fail-closed readiness, sender-domain checks, read-only pagination, and provider errors. Frontend and backend production bundles built successfully; workflows restarted. The app-side Resend adapter passed a real read-only domain check. Public routes stayed accessible and anonymous readiness/publishing/campaign requests returned HTTP 401.
  • Not tested live: administrator sign-in, the new authenticated readiness panel, binary extraction, generated EPUB validity, provider TTS, real email delivery, job restart recovery, payment, or cross-device account synchronization. Full backend type-checking still reports pre-existing missing-return errors in legacy handlers; no publishing-module type errors were reported.

Evidence comes from the development preview and current source. Existing synthetic catalog entries and metrics are not proof of real sales, generation, consent, or delivery.

Recommended login policy

No login: browsing, search, categories, book information, free samples, publicly offered audio previews, and valid unsubscribe links.

Reader login: a persistent personal bookshelf, cross-device progress, saved notes/highlights, account management, membership, purchase history, and services that incur AI usage. A real purchase must also establish a server-verified entitlement.

Administrator only: source uploads, draft manuscripts, private generated assets, catalog mutation, publication approval, campaign recipients/sending, subscriber imports, operational metrics, and configuration.

The separate public-reading/admin-separation work already covers the broader navigation and login-policy changes. This audit does not claim those changes have been implemented.

Publishing: implementation and test order

  1. Block false success — initial safety guard implemented. Legacy ingest and campaign sends are disabled, fake progress is removed, notification defaults are off, and readiness distinguishes configured from verified. The replacement must preserve fail-closed behavior for incomplete stages.
  2. Connect dependencies. Configure direct Gemini text/multimodal and speech access, existing Supabase, private file storage, and an email provider with a verified sender.
  3. Build a durable draft pipeline. Upload → extract/OCR → outline → full chapters → validated EPUB → chapter audio → administrator preview. Use real job records and progress, not timers.
  4. Add explicit publication approval. Default to draft/review. If automatic publication is offered, require deliberate opt-in and completed required assets. Never invent ISBNs or reviews.
  5. Add controlled campaign delivery. Respect separate publisher/reader switches, consent, suppressions, unsubscribe, deduplication, and the difference between queued, accepted, delivered, and failed.
  6. Run one bounded fixture through the full system. Use a short synthetic manuscript, validated PDF/image fixtures, and an allowlisted test inbox. Confirm actual EPUB contents and playable audio, then test failure, retry, reload, and restart behavior.

Safety boundary: fixture tests must not publish into the live storefront or email existing readers. No live campaign or production database mutation has been authorized as part of this audit.

Current setup blockers

  • AI: direct Gemini credentials and model access are verified through free metadata requests. Google routes the requested gemini-3.7-flash identifier to 3.8 Flash; gemini-3.8-flash-tts is available for speech. No paid generation has run. The user authorized a synthetic generation/audio test with a US$1 total limit.
  • Database: the user chose isolated bookatlas_ tables in the shared Supabase project. Repository access and schema probes now use only those tables. The updated artifacts/api-server/src/bookatlas/db/schema.sql changes only prefixed tables, enables row-level security, and inserts no demo data. Eight focused tests passed, including namespace isolation checks. Applying the schema still requires PostgreSQL administrator access or the Supabase SQL Editor. No schema changes or demo inserts have been made remotely.
  • Storage: App Storage is provisioned. Protected uploads, output writes, and authorized playback/downloads still need implementation and verification.
  • Email: Resend is connected, its sending-domain check passed, and the user selected a sender mailbox. Explicit recipient consent, controlled test-recipient configuration, and durable send records are still required.

Until these dependencies and the implementation are in place, complete multimodal publishing and real campaign delivery remain blocked, not passed.
