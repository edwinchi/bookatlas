Development audit · 21 October 2026

Bookatlas: what works, what is simulated, and what publishing needs

This is an audit of the development app, not a claim that every interactive journey passed a browser test. A synthetic book was published only to an isolated test catalog. No book was added to the public storefront. One explicitly approved connection-test email was sent and Resend confirmed delivery; no reader campaign was sent.

Main finding: the simulated publishing endpoints remain blocked. A real, guarded replacement is now connected to the studio: private uploads, persisted jobs and spending reservations, source extraction, complete chapters, EPUB, chapter narration, review and publication. A real two-chapter book/audio fixture and PDF/image extraction checks passed. The rest of the site still contains demo commerce, legacy timer playback and unverified flows; it is not ready to accept real payments.

What was actually checked

  • Live HTTP checks: public health, catalog, and category endpoints returned HTTP 200. Anonymous requests to manager statistics and email-dispatch logs returned HTTP 401.
  • Public desktop screenshot: the catalog renders without requiring sign-in. Internal-tool links remain visible in the public navigation. One resource returned HTTP 404; its cause has not yet been isolated.
  • Implementation review: publishing, campaign processing, reading/audio controls, checkout, account access policy, catalog persistence, and the principal frontend API calls were inspected.
  • Configuration check: all eight isolated Bookatlas tables now pass required-column checks in the selected Supabase project. Text and speech model access, private App Storage writes/reads, and Resend sender-domain access were exercised. Old-project service credentials are not reused. A single approved test email was accepted and subsequently reported delivered by Resend. Its deduplicated send record and delivery status are persisted.
  • Safety changes verified: five focused unit tests passed for fail-closed readiness, sender-domain checks, read-only pagination, and provider errors. Frontend and backend production bundles built successfully; workflows restarted. The app-side Resend adapter passed a real read-only domain check. Public routes stayed accessible and anonymous readiness/publishing/campaign requests returned HTTP 401.
  • Publishing checks: 34 focused checks pass for source/file integrity, complete page accounting/unreadable-page rejection, EPUB contents, WAV structure/duration, immutable budget accounting, scoped database credentials, access policy, consent eligibility and signed unsubscribe tokens. Production web/API bundles build. The job worker persists a conservative reservation before every paid call, retains ambiguous attempts, uses version/lease checks and resumes completed stages rather than rebilling them.
  • Real provider fixtures: a source-grounded two-chapter EPUB and two complete chapter WAV files were generated, read back from private storage, and published only to the test catalog. Actual audio durations were 53.04 and 44.60 seconds. The public book table did not contain the fixture. Separate real PDF and PNG extraction checks recovered the expected synthetic text through the same extraction function used by the worker. Conservative reservations across all attempts total US$0.393077; combined fixture caps were US$0.95, within the authorized US$1. This is a safety reservation, not an invoice total. A truncated chapter and an interrupted image attempt were recovered within their original caps.
  • Still not verified: a complete signed-in administrator/reader browser journey, actual in-browser audio playback, third-party EPUB conformance/reader compatibility, a full publication-to-campaign launch and unsubscribe journey, hard process-crash lease recovery, real payments and cross-device personal-state synchronization. The connection-test email alone does not verify these journeys. Legacy backend missing-return errors and two EditorialBlock type errors remain; changed publishing modules have no reported type errors.

Evidence comes from the development preview and current source. Existing synthetic catalog entries and metrics are not proof of real sales, generation, consent, or delivery.

Recommended login policy

No login: browsing, search, categories, book information, free samples, publicly offered audio previews, and valid unsubscribe links.

Reader login: a persistent personal bookshelf, cross-device progress, saved notes/highlights, account management, membership, purchase history, and services that incur AI usage. A real purchase must also establish a server-verified entitlement.

Administrator only: source uploads, draft manuscripts, private generated assets, catalog mutation, publication approval, campaign recipients/sending, subscriber imports, operational metrics, and configuration.

The separate public-reading/admin-separation work already covers the broader navigation and login-policy changes. This audit does not claim those changes have been implemented.

Publishing: implemented workflow and verification limits

  1. Block false success — initial safety guard implemented. Legacy ingest and campaign sends are disabled, fake progress is removed, notification defaults are off, and readiness distinguishes configured from verified. The replacement must preserve fail-closed behavior for incomplete stages.
  2. Dependencies connected and exercised. Direct Gemini text/multimodal and speech access, the selected isolated Supabase tables, private file storage, and Resend with a verified sender are configured. One approved connection-test email was reported delivered.
  3. Build a durable draft pipeline. Upload → extract/OCR → outline → full chapters → validated EPUB → chapter audio → administrator preview. Use real job records and progress, not timers.
  4. Add explicit publication approval. Default to draft/review. If automatic publication is offered, require deliberate opt-in and completed required assets. Never invent ISBNs or reviews.
  5. Add controlled campaign delivery. Respect separate publisher/reader switches, consent, suppressions, unsubscribe, deduplication, and the difference between queued, accepted, delivered, and failed.
  6. Bounded fixtures passed for generation, audio, EPUB, persistence, review/test publication and PDF/image extraction. One separately approved test email was reported delivered, without emailing readers or enabling live mode. Reload/read-back and checkpoint retry were exercised; signed-in browser interactions, the full campaign/unsubscribe flow and hard process-crash recovery remain separate verification work.

Safety boundary: fixture tests must not publish into the live storefront or email existing readers. No live campaign or production database mutation has been authorized as part of this audit.

Ready dependencies and remaining rollout conditions

  • AI: real generation, narration and extraction calls passed within the authorized aggregate cap. Google routes gemini-3.7-flash to 3.8 Flash; narration uses gemini-3.8-flash-tts. Preview/editing remains necessary: model completion is not a factual-quality guarantee.
  • Database: the selected replacement project and all eight bookatlas_ tables are ready. New-project secret-key mode avoids credential crossover; no old-project records were copied and unrelated tables were not modified.
  • Storage: private source and output writes/reads passed. Browser downloads use signed-in API authorization rather than public object URLs. Verify permissions again for a production runtime.
  • Email: the sender domain is verified and one approved connection-test email was reported delivered by Resend. The verified published app URL is configured. Live campaigns remain disabled in test mode. Publish the current build before verifying the full campaign/unsubscribe journey; live-mode authorization is still required.

Ready: guarded draft creation, real EPUB/chapter narration, review and isolated test publication. Not claimed: verified live campaign delivery, production-ready payments, complete public/admin navigation separation or a full signed-in browser test.
